8. AI Control (MCP)

Let an LLM (Claude Desktop, Claude Code, or any other MCP-capable client) drive a running simple-daw instance directly — add tracks, program a beat, tweak a synth patch, hit play — through a small local companion process.

How it works

Two pieces, both running entirely on your machine:

  • simple-daw itself opens a local control socket in the background as soon as it starts (a Unix domain socket at $TMPDIR/simple-daw.sock). Any command it receives is applied to the live song through the same code paths the UI uses, so changes appear on screen — and play back — immediately.
  • simple-daw-mcp is a separate binary built from the same repository. It speaks the Model Context Protocol over stdio to whatever launched it (Claude Desktop, Claude Code, etc.) and forwards each tool call to that socket.
Nothing about the song leaves your machine through this feature. simple-daw and simple-daw-mcp talk over a local socket only — whether the LLM host itself sends your conversation to a cloud API is a separate matter, unrelated to this integration.

Requirements

  • macOS or Linux — the control socket is Unix-domain-only. It's simply not compiled in on other platforms.
  • simple-daw must already be running before a tool call is made; the companion binary doesn't launch it for you.
  • Only one simple-daw instance at a time — the socket path is fixed, so a second instance would fight the first for it.

Setup

Build both binaries:

cargo build --release

This produces target/release/simple-daw (the app) and target/release/simple-daw-mcp (the MCP server) side by side.

Point your MCP client at simple-daw-mcp. For Claude Desktop, add it to the MCP servers section of the app's config file:

{
  "mcpServers": {
    "simple-daw": {
      "command": "/absolute/path/to/target/release/simple-daw-mcp"
    }
  }
}

Restart the MCP client after editing its config, launch simple-daw, and the tools below become available in your conversation.

Using it

Once connected, you can ask in plain language and the model will call the tools it needs, for example:

  • "Add a step-grid track called Drums and program a basic four-on-the-floor kick pattern."
  • "What tracks are in the song right now?"
  • "Set the tempo to 128 BPM and hit play."
  • "Apply the Warm Pad preset to track 2."
  • "Export the song to ~/Desktop/demo.wav, looping it twice."
Tracks, regions, lanes and steps are all referenced by 0-based index — the same indices list_tracks/list_presets report. Ask the model to list tracks first if you're not sure which index something is.

Available tools

ToolWhat it does
list_tracksList every track — name, kind, mute/solo, volume, synth engine.
add_trackAdd a track (step_grid, piano_roll, or audio). Returns its index.
remove_trackDelete a track and everything it owns.
set_track_volumeSet a track's mix volume.
set_track_muteMute/unmute a track.
set_track_soloSolo/unsolo a track.
add_regionAdd a one-bar region to a track at a given step. Returns its index.
add_laneAdd a step-grid lane (e.g. a drum voice) to every region on a track.
set_stepSet or clear one step in a step-grid lane — the core beat-programming tool.
add_noteAdd a note to a piano-roll region.
list_presetsList factory and song-local synth presets, optionally filtered by engine.
apply_presetApply a preset to a track by name, switching its synth engine to match.
set_bpmSet the song's tempo.
play / stopStart/stop playback.
get_playback_stateWhether the song is playing, the playhead position, bpm, song name.
save_songSave the song to a JSON file at the given path.
load_songLoad a song from a JSON file, replacing the currently open one.
export_wavBounce the song to a WAV file — same export path as the File menu's Export dialog.

Current limitations

  • No tool yet for loading or configuring CLAP effects — that's still UI-only (see Mixing & Effects).
  • load_song/save_song mirror the File menu's Load/Save, but there's no MCP equivalent of Save As — it always writes to the given path.
  • Audio-track clips (recording/importing WAV) aren't exposed as tools yet; use the app's own recording workflow for those.

Troubleshooting

SymptomLikely cause
Tool calls fail with "couldn't reach simple-daw … is the app running?" Launch simple-daw first — the companion binary only forwards to an already-running instance.
A tool call errors with something like "no track at index 3" Indices shifted since you last checked — call list_tracks (or list_presets) again before referencing one.
Nothing happens after restarting simple-daw A stale socket file from a crashed previous run can linger; the app removes and re-binds it on startup automatically, so this normally resolves itself — if not, quit every simple-daw process and relaunch one.
