Technical Documentation

How the song is represented and how it's turned into sound — for anyone reading or modifying the source, not just using the app.

Looking to learn the app itself instead? See the User Manual.

Project layout

The crate is a flat set of top-level src/*.rs files, each one responsibility (data model, audio engine, UI, built-in effect DSP, CLAP hosting, sample loading, wavetables, MIDI import, groove/tempo/pitch/stretch DSP). The repository's own CLAUDE.md is the canonical, most detailed architecture reference — the two pages here are a narrower, doc-site-formatted view of the same ground, focused on the parts most useful to get oriented in the codebase.

Data Model

src/model.rs — Song → Track → Region/AudioClip, and every field that hangs off them.

Engine Architecture

The real-time audio thread, voice pools, the stereo signal path, the mixer bus graph, automation evaluation, and the tempo/groove/stretch subsystems.

Commands

cargo build              # debug build
cargo run                # launch the GUI app
cargo test                # unit tests: audio DSP math, model editing logic, WAV export
cargo test <test_name>     # run a single test (matches by substring)
cargo clippy --all-targets # lint, including test code
Unit tests cover synth/DSP math and the WAV exporter, but there's no automated harness for the live audio path — verify audio-affecting changes by running the app manually (cargo run).
